# Frontend stack research (official docs only) — verified 2026-10-18

## 1. Next.js (App Router)
**Current stable: 16.4.x** (npm `latest` = 16.4.2; release post 6 Oct 2026). Ships **React 19.3**. Node >= 20.9, TS >= 5.1, Turbopack default for dev+build.
- Version/React: https://nextjs.org/blog/next-16-4 · requirements: https://nextjs.org/docs/app/guides/upgrading/version-16
- Production checklist (`"use client"` boundaries low, Route Handlers from Client Components only, parallel fetching, `<Image>`/`next/font`/`<Script>`, `eslint-plugin-jsx-a11y`, `useReportWebVitals`, bundle analysis): https://nextjs.org/docs/app/guides/production-checklist
- Caching: `cacheComponents: true` + `partialPrefetching: true` is now the recommended model (default in create-next-app since 16.4; PPR is the default rendering). `'use cache'` + `cacheLife()` + `cacheTag()` are stable; uncached async/runtime data MUST be wrapped in `<Suspense>` or the build errors (blocking-route). `revalidateTag(tag, 'max')` (SWR) vs `updateTag(tag)` (read-your-writes, Server Actions only). Route-segment `dynamic`/`revalidate`/`fetchCache`/`runtime` are removed when cacheComponents is on. https://nextjs.org/docs/app/getting-started/caching · https://nextjs.org/docs/app/guides/upgrading/version-16#caching-apis
- Server vs Client Components: SCs default; CCs for state/events/effects/browser APIs; put `'use client'` on leaf interactive files; pass SCs as `children` into CCs; render context providers as deep as possible; `server-only` import guards. https://nextjs.org/docs/app/getting-started/server-and-client-components
- Streaming/Suspense: prefer granular sibling `<Suspense>` boundaries over `loading.js`; push `await params/cookies/fetch` down into the component that needs it; skeletons sized to content (CLS); each boundary = hydration unit (INP); keep LCP element outside Suspense; disable nginx buffering (`X-Accel-Buffering: no`). https://nextjs.org/docs/app/guides/streaming · https://nextjs.org/docs/app/api-reference/file-conventions/loading
- Route Handlers for SSE: return `new Response(new ReadableStream(...), { headers: {'Content-Type': 'text/event-stream', 'X-Content-Type-Options':'nosniff'} })`; GET handlers are dynamic by default since v15; runtime is `'nodejs'` by default and `'edge'` is deprecated (omit `runtime` export under cacheComponents). https://nextjs.org/docs/app/api-reference/file-conventions/route · https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config/runtime
- Lazy loading: `next/dynamic` (= `React.lazy` + Suspense); `ssr:false` only inside Client Components; `import()` heavy libs on demand. https://nextjs.org/docs/app/guides/lazy-loading
- Images: `width`/`height` or `fill` required (CLS); `sizes` whenever `fill`/responsive CSS, otherwise browser assumes 100vw; `preload` (replaces deprecated `priority`) only for the single LCP image; lazy by default; `remotePatterns` (not `domains`); `qualities` default `[75]`. https://nextjs.org/docs/app/api-reference/components/image
- Fonts: `next/font/google` self-hosts, zero external requests, `display:'swap'`, `subsets:['latin']`, variable fonts; expose `variable: '--font-inter'` and map via `@theme inline { --font-sans: var(--font-inter) }` in Tailwind v4. https://nextjs.org/docs/app/api-reference/components/font
- Bundles: `npx next analyze` (Turbopack analyzer, v16.1+; `--output`, snapshots/diff in 16.4), `experimental.optimizePackageImports` for icon libs, move data-to-UI transforms (charts/markdown) into Server Components. https://nextjs.org/docs/app/guides/package-bundling
- Instrumentation: root `instrumentation.ts` exporting `register()` (runs once per server start; gate imports on `process.env.NEXT_RUNTIME`). https://nextjs.org/docs/app/guides/instrumentation
- React Compiler: `reactCompiler: true` is stable config (not default; Babel cost); experimental Rust compiler `experimental.turbopackRustReactCompiler`. https://nextjs.org/docs/app/guides/upgrading/version-16#react-compiler-support
- Accessibility built-ins: route announcer (reads `document.title` -> `<h1>` -> path; give each page a unique title); `eslint-plugin-jsx-a11y` rules. https://nextjs.org/docs/architecture/accessibility
- Metadata: Metadata API / OG images per checklist. https://nextjs.org/docs/app/getting-started/metadata-and-og-images

## 2. React
**Current stable: 19.3.x** (19.3.0 released 9 Sep 2026; npm latest 19.3.1). https://react.dev/versions · https://react.dev/blog/2026/09/09/react-19-3
**React Compiler: stable v1.0** since 7 Oct 2025. https://react.dev/blog/2025/10/07/react-compiler-1 · install: https://react.dev/learn/react-compiler/installation
- `useTransition`: mark non-urgent updates (tab/filter/list re-render) as interruptible; `isPending` for inline feedback; **cannot** be used for controlled text input state — use two state vars or `useDeferredValue`. https://react.dev/reference/react/useTransition
- `useDeferredValue`: keep `query` in sync state, pass `deferredQuery` to the heavy list; slow child must be wrapped in `memo` (compiler does this automatically); show stale indicator with `query !== deferredQuery`; adaptive, interruptible — unlike debounce; still debounce network requests separately. **This is the recommended pattern for responsive search/filter inputs (Q9).** https://react.dev/reference/react/useDeferredValue
- `memo`/`useMemo`/`useCallback`: only when re-render is measurably slow (>~1ms via `console.time`, profile in production build with CPU throttling); prefer children-as-JSX, local state, pure rendering, no state-setting Effects; with React Compiler manual memo is usually unnecessary. https://react.dev/reference/react/memo · https://react.dev/reference/react/useMemo
- Suspense: group related content in one boundary, nest for staged reveal, don't wrap everything; `startTransition` prevents already-shown content reverting to fallback; `key` resets boundary; only `use(promise)`/RSC/`lazy` trigger it — fetching in `useEffect` does not. https://react.dev/reference/react/Suspense
- Purity: components must be pure (StrictMode double-render catches violations); side effects in event handlers, `useEffect` last; purity is what lets React skip/interrupt renders. https://react.dev/learn/keeping-components-pure
- 19.3 perf notes: Transitions render independently (slow one no longer blocks others), resize updates batched, `useDeferredValue` stuck-value fix; stable `<ViewTransition>`, Fragment refs, `use(browser())` for client-only subtrees.

## 3. TanStack Query
**Current stable: v5 — 5.104.4** (17 Oct 2026); peer React ^18 || ^19. https://github.com/TanStack/query/releases
- Important defaults: `staleTime: 0`, `gcTime: 5min`, refetch on mount/window focus/reconnect when stale, `retry: 3` with backoff, structural sharing on. https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults
- Render optimizations: structural sharing keeps references stable; tracked properties (don't rest-destructure the result); `select` for subsets (stable fn via `useCallback`/module scope); `notifyOnChangeProps`. https://tanstack.com/query/latest/docs/framework/react/guides/render-optimizations
- App Router SSR/hydration: `makeQueryClient()` per request on server + browser singleton; set default `staleTime` (~60s) so hydrated data isn't refetched immediately; prefetch in Server Component with `queryClient.prefetchQuery`/`query` (prefetchQuery now deprecated in favour of `query(...).catch(noop)`), wrap in `<HydrationBoundary state={dehydrate(queryClient)}>`, consume with `useSuspenseQuery`; optional streaming of pending queries via `shouldDehydrateQuery`; don't use Server Actions as `queryFn`. https://tanstack.com/query/latest/docs/framework/react/guides/advanced-ssr
- Optimistic updates: UI approach (`variables` + `isPending`, no rollback) when one place renders it; cache approach (`onMutate`: `cancelQueries` -> `getQueryData` snapshot -> `setQueryData`; `onError` rollback; `onSettled` `invalidateQueries`) when many components show the data. https://tanstack.com/query/latest/docs/framework/react/guides/optimistic-updates
- Invalidation: `invalidateQueries({ queryKey })` marks stale (prefix match by default; `exact`, `predicate`) and refetches active queries; `refetchType: 'none' | 'active' | 'all'`. https://tanstack.com/query/latest/docs/framework/react/guides/query-invalidation · https://tanstack.com/query/latest/docs/framework/react/reference/QueryClient
- WebSocket binding pattern (from API reference semantics): on socket event, either `queryClient.setQueryData(key, updater)` with the payload (no refetch) or `queryClient.invalidateQueries({ queryKey })` to refetch; set `staleTime: Infinity` on socket-driven queries so only events trigger refetch. **Flag:** TanStack has no dedicated official "WebSockets" guide; the commonly cited article is TkDodo's blog (community, linked from docs), not vendor docs.
- Server-pagination pairing: put `pagination`/`sorting`/`filters` in the query key, use `placeholderData: keepPreviousData` to avoid flicker (shown in TanStack Table v9 pagination guide).

## 4. TanStack Table + TanStack Virtual
**Table current stable: v9 — @tanstack/react-table 9.3.1** ("latest" docs now v9; peer React >=18; ~25 KB brotli full, tree-shakable features via `tableFeatures()`/`useTable`). https://tanstack.com/table/latest/docs/overview · https://github.com/TanStack/table/releases
**Virtual current stable: @tanstack/react-virtual 3.14.21.** https://github.com/TanStack/virtual/releases
- Table has NO built-in virtualization; pair with TanStack Virtual. `useVirtualizer({ count: rows.length, getScrollElement, estimateSize: () => 33, overscan })`; scroll container must have fixed height; render `getVirtualItems()` only; `tbody` height = `getTotalSize()`, rows `position:absolute; transform: translateY(start)`; `measureElement` + `data-index` only for variable-height rows; `display:grid` on table/thead with sticky header. https://tanstack.com/table/v9/docs/framework/react/guide/virtualization
- Virtualization reduces DOM only — data still fully loaded; use server pagination / infinite scroll when dataset is too large; small tables: don't virtualize. (same URL)
- Virtual API: `overscan` default 1; `estimateSize` should estimate the largest comfortable size; `scrollToIndex(i, {align, behavior})`; `useWindowVirtualizer` + `scrollMargin` for lists under a header. https://tanstack.com/virtual/latest/docs/api/virtualizer
- Server-side pagination: `manualPagination: true` + `rowCount` (or `pageCount`, `-1` if unknown); controlled state via `state.pagination` + `onPaginationChange` (v8-style) or v9 `atoms` for fine-grained subscriptions; `autoResetPageIndex` auto-disabled under manual; TanStack Query example uses `placeholderData: keepPreviousData`. https://tanstack.com/table/v9/docs/framework/react/guide/pagination
- Client-side pagination: register `rowPaginationFeature` + `createPaginatedRowModel()`; v8 docs say tens of thousands of rows is fine client-side — "several hundred records" needs no server paging for render performance. https://tanstack.com/table/v8/docs/guide/pagination
- v8 -> v9 migration guide: https://tanstack.com/table/latest/docs/framework/react/guide/migrating (v8 docs remain at /table/v8/).

## 5. Tailwind CSS
**Current stable: v4.3.x** (npm latest 4.3.3; v4.3 post 8 May 2026). https://tailwindcss.com/blog/tailwindcss-v4-3
- Engine: v4.0 rewrite — full builds 3.5–5x faster, incremental builds 8x–100x+ (microseconds when no new CSS); `@tailwindcss/webpack` loader 2.17x faster than PostCSS path in Next.js/Turbopack benchmark (932ms -> 429ms). https://tailwindcss.com/blog/tailwindcss-v4 · https://tailwindcss.com/blog/tailwindcss-v4-3
- Install with Next.js: `npm i tailwindcss @tailwindcss/postcss postcss`; `postcss.config.mjs` = `{ plugins: { "@tailwindcss/postcss": {} } }`; `@import "tailwindcss";` in `app/globals.css`; no `tailwind.config.js`, remove `postcss-import`/`autoprefixer`. https://tailwindcss.com/docs/installation/framework-guides/nextjs · https://tailwindcss.com/docs/upgrade-guide
- Unused CSS: automatic content detection scans all non-gitignored, non-binary, non-CSS files as plain text and only emits utilities actually present — so **never build class names by string interpolation** (`text-${color}-600`); map props to complete class strings; `@source` for UI libs in node_modules, `@source not`, `@source inline()` safelist, `source(none)` to disable auto-detection. https://tailwindcss.com/docs/detecting-classes-in-source-files
- CSS-first config via `@theme { --color-...; --breakpoint-3xl: 1920px }`; tokens emitted as CSS variables. https://tailwindcss.com/blog/tailwindcss-v4
- Browser floor: Safari 16.4+, Chrome 111+, Firefox 128+ (matches Next.js 16 floor). https://tailwindcss.com/docs/upgrade-guide
- Responsive/a11y helpers in 4.3: `scrollbar-gutter-stable` prevents layout shift; `@container-size` for container queries. https://tailwindcss.com/blog/tailwindcss-v4-3

## 6. shadcn/ui + primitives (Radix / Base UI)
**shadcn CLI current: 4.22.0** (CLI v4 since Mar 2026). **Since July 2026 Base UI (`@base-ui/react` 1.9.0) is the default primitive; Radix (`radix-ui` 1.8.1) remains fully supported — `npx shadcn init -b radix` keeps Radix.** https://ui.shadcn.com/docs/changelog/2026-07-base-ui-default · install: https://ui.shadcn.com/docs/installation/next
- Radix a11y guarantees: WAI-ARIA Authoring Practices roles/aria attrs, keyboard support, focus management (e.g., AlertDialog focuses Cancel), tested with assistive tech; **labels are the developer's job** (Label primitive / `htmlFor` + `id`); **contrast not covered**. https://www.radix-ui.com/primitives/docs/overview/accessibility
- Radix Dialog: focus trapped, Esc closes and returns focus to trigger, Tab/Shift+Tab cycle, `Dialog.Title` required (announced), `Dialog.Description` optional. https://www.radix-ui.com/primitives/docs/components/dialog
- Radix Select: ListBox pattern, Arrow/Enter/Space/Esc + typeahead, label via `Label htmlFor` + `Select.Trigger id`. https://www.radix-ui.com/primitives/docs/components/select
- Base UI a11y: ARIA + roles handled; arrow/Home/End/Enter/Esc keyboard; automatic focus management (`initialFocus`/`finalFocus`); Form/Field/Fieldset auto-associate labels; developer must style `:focus-visible`, ensure contrast (APCA recommended), and provide accessible names. https://base-ui.com/react/overview/accessibility
- shadcn Field components: `FieldLabel htmlFor`, `aria-invalid` + `data-invalid` on controls, `FieldDescription`, `FieldError`, `aria-label` on icon-only buttons; integrates RHF `Controller` + `zodResolver`. https://ui.shadcn.com/docs/forms/react-hook-form
- `cn` now a separate package (`npx shadcn@latest migrate cn`). https://ui.shadcn.com/docs/changelog

## 7. react-hook-form + Zod
**RHF current stable: 7.90.0** (10 Oct 2026; v8 in beta). **@hookform/resolvers 5.9.2** (peer `zod ^3.25 || ^4`). **Zod current stable: 4.x** (npm 4.6.7). https://github.com/react-hook-form/react-hook-form/releases · https://zod.dev/
- Performance model: uncontrolled inputs via `register` (ref, not value/onChange) → typing doesn't re-render the form; `Controller`/`useController` scope re-renders to one field for controlled UI libs (shadcn/Select); Proxy-based `formState` subscription — only properties you read trigger re-renders (destructure, read before render). https://react-hook-form.com/faqs · https://react-hook-form.com/get-started
- Isolation hooks: `useWatch` re-renders only the calling component (vs `watch` at form root); `useFormState` subscribes per component, `name`/`exact` narrow it. https://react-hook-form.com/docs/usewatch · https://react-hook-form.com/docs/useformstate
- `FormProvider` is Context: whole subtree re-renders on state change; `memo` nested inputs if needed. https://react-hook-form.com/advanced-usage
- Accessibility pattern: `<label htmlFor>` + `id`, `aria-invalid={!!errors.x}`, error message with `role="alert"`. https://react-hook-form.com/advanced-usage#AccessibilityA11y
- Zod resolver: `useForm({ resolver: zodResolver(schema) })`, types via `z.infer`; Zod 4 needs resolvers >= 3.10 and `moduleResolution: bundler|node16|nodenext`. https://github.com/react-hook-form/resolvers
- Zod 4 perf: 14x faster string, 7x array, 6.5x object parsing vs v3; 100x fewer TS instantiations; `zod/mini` 1.88 kB gz; requires TS >= 5.5 with `strict`. https://zod.dev/v4
- Default validation `mode` is `onSubmit`; use `onBlur`/`onTouched` for inline feedback without per-keystroke validation. https://ui.shadcn.com/docs/forms/react-hook-form
- **Flag:** react-hook-form.com returned HTTP 403 to the fetcher; content verified from the official docs repo (github.com/react-hook-form/documentation) and FAQ snippets.

## 8. socket.io-client
**Current stable: 4.8.4** (Sep 2026); 14.7 kB min+gz; compatible with server 3.x/4.x. https://socket.io/docs/v4/client-installation/
- Reconnection defaults: `reconnection: true`, `reconnectionAttempts: Infinity`, `reconnectionDelay: 1000`, `reconnectionDelayMax: 5000`, `randomizationFactor: 0.5`, `timeout: 20000`; `auth` for tokens/tenant; `autoConnect: false` until the user is authenticated. https://socket.io/docs/v4/client-options/
- Acknowledgements: callback as last `emit` arg; `socket.timeout(5000).emit(...)`; `await socket.emitWithAck(ev, data)` (v4.6+); at-least-once client→server via `retries` + `ackTimeout`. https://socket.io/docs/v4/client-api/ · https://socket.io/docs/v4/delivery-guarantees
- Default delivery is at-most-once; server does not buffer for disconnected clients — on `connect` (every reconnection) when `socket.recovered === false`, resync by `queryClient.invalidateQueries()` for live queries. https://socket.io/docs/v4/delivery-guarantees · https://socket.io/docs/v4/connection-state-recovery
- Lifecycle: `connect`, `disconnect(reason)` (`io server disconnect` won't auto-reconnect), `connect_error`; manager events `socket.io.on('reconnect_attempt'|'reconnect')`. Never register listeners inside the `connect` handler. https://socket.io/docs/v4/client-socket-instance/
- React pattern: module-level singleton `socket = io(URL, {autoConnect:false})`; one `useEffect([])` for connect/disconnect (StrictMode-safe), a separate effect for `socket.on(ev, handler)` with `socket.off(ev, handler)` cleanup; functional state updates. https://socket.io/how-to/use-with-react
- Binding to Query: in the listener effect, `socket.on('lead:updated', (lead) => queryClient.setQueryData(['lead', lead.id], lead))` and `queryClient.invalidateQueries({ queryKey: ['leads'] })`; `socket.volatile.emit` for presence/typing. https://socket.io/docs/v4/emitting-events/
- Transports default `["polling","websocket","webtransport"]`; serialization is automatic (don't `JSON.stringify`; `Date` becomes string, `Map`/`Set` need conversion).
